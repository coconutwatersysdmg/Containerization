# 托盘什么时候算“装完了”？

> 一句话：**这一盘上的箱子指数加起来，达到（或超过）规定的目标，就算装完。**

---

## 先搞懂两个词

### 1. 箱子指数（每个箱子自带的分）

- 每个箱子都有一个数字，叫 **`min_pack_multiple`**（最小包装量倍数）。
- 这个数字**不是**从 WCS 接口传的，是算法根据**箱型**去 Excel 的 BMS 表里查出来的。
- 可以理解为：**这个箱子在拼 Case 里占多少“分”**。

举例：

| 箱型   | 箱子指数 |
|--------|----------|
| YZX448 | 1        |
| ZX444  | 2        |
| YZX424 | 4        |

---

### 2. 托盘目标指数（这一盘要凑到多少分）

- 每种托盘类型（Case 类型）有一个**目标分数**，叫 **`mpm_target`**。
- 目标分数写在代码配置文件里：

  文件：`code/src/config/constants.py`

  ```python
  PALLET_INDEX_TARGETS = {
      "MH423C": 15,   # MH423C 这种托盘，一盘要凑够 15 分
      "MH110": 32,    # MH110 这种托盘，一盘要凑够 32 分
  }
  ```

- 查表用的 key 是 **`pallet_type`**（也就是 Case 类型，比如 `MH423C`）。
- **WCS 接口不会传这个目标值**，是算法自己按托盘类型查的。

---

## 装完的标准（核心公式）

```
这一盘的总分 = 盘上所有箱子的 min_pack_multiple 相加

如果：总分 >= 目标分数（mpm_target）
那么：这一盘算装完（指数达标）
```

输出 JSON 里对应字段：

| 字段         | 含义                         |
|--------------|------------------------------|
| `mpm_total`  | 这一盘现在的总分             |
| `mpm_target` | 这一盘的目标分               |
| `mpm_gap`    | 还差多少 = 目标 - 总分（负数表示已超过） |
| `mpm_status` | `SUCCESS` = 装完了（达标）   |

---

## 举个具体例子

假设托盘类型是 **MH423C**，目标指数是 **15**。

这一盘放了这些箱子：

| 箱子   | 箱子指数 |
|--------|----------|
| 箱 A   | 1        |
| 箱 B   | 1        |
| 箱 C   | 2        |
| …      | …        |
| 合计   | **59**   |

- `mpm_total` = 59  
- `mpm_target` = 15  
- 59 >= 15 → **`mpm_status` = `SUCCESS`** → **算装完了**

即使目标只是 15，算法也可能往盘上多装一些箱子（为了摆稳、填空间等），所以总分常常会**大于**目标，这也是正常的。

---

## 三种状态分别是什么意思

| mpm_status | 什么意思 | 怎么办 |
|------------|----------|--------|
| **SUCCESS** | 总分 >= 目标，**装完了** | 可以当作拼 Case 成功 |
| **FAILED**  | 总分 < 目标，**没装够** | 算法会尝试各种“救援”手段再补救 |
| **UNKNOWN** | 这种托盘类型没配目标分 | 不按分数判断，尽量多装 |

---

## 和“物理装完”的区别（别搞混）

| 问题 | 答案 |
|------|------|
| 是不是装满托盘所有空间才算完？ | **不是**。看的是**指数总分**，不是体积满不满。 |
| 是不是 WCS 传一个“完成标准”过来？ | **不是**。目标分在 `constants.py` 里写死（按托盘类型查）。 |
| 箱子上的 `min_pack_multiple` 是目标吗？ | **不是**。那是**每个箱子贡献的分**，目标分是**整盘要凑的总分**。 |
| `fill_rate`（填充率）是装完标准吗？ | **不是**。填充率只是统计信息，**不影响**是否算装完。 |

## 数据从哪来（一张图看懂）

```
┌─────────────────────────────────────────────────────────┐
│  WCS / Excel 输入                                        │
│  · 箱型 box_type                                         │
│  · Case 类型 case_type → 对应 pallet_type（如 MH423C）   │
└───────────────────────┬─────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────┐
│  BMS 表（Excel）                                         │
│  箱型 → min_pack_multiple（每个箱子多少分）              │
└───────────────────────┬─────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────┐
│  constants.py                                          │
│  pallet_type → mpm_target（这一盘要多少分）              │
└───────────────────────┬─────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────┐
│  算法装箱                                                │
│  一盘一盘装，每装完一盘算一次总分                        │
│  总分 >= 目标 → 这一盘 SUCCESS（装完）                   │
└─────────────────────────────────────────────────────────┘
```

## 想改“装完标准”改哪里

改 **`code/src/config/constants.py`** 里的 `PALLET_INDEX_TARGETS`：

```python
PALLET_INDEX_TARGETS = {
    "MH423C": 15,   # 改成你想要的数，比如 192
    "MH110": 32,
}
```

改完后重新跑装箱，输出 JSON 里的 `mpm_target` 就会变。

> 注意：项目里还有一个 `config.yaml` 也写了 `target_index: 192`，但**当前 `run_packing.py` 不会读它**。以 `constants.py` 为准。

## 最短版（给赶时间的人）

1. 每个箱子有分数 → `min_pack_multiple`（BMS 表查）  
2. 每种托盘有目标 → `mpm_target`（`constants.py` 查）  
3. **盘上分数加起来 >= 目标 → 装完**  
4. 看 JSON 里的 `mpm_status` 是不是 `SUCCESS`
